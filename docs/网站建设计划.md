# app.zhihaojiang.com 网站建设计划

## 目标

建立一个个人软件目录，统一收录自己制作的软件和自己推荐的软件。所有软件在同一个列表中展示，仅通过软件旁的「自己制作」或「推荐」标识区分来源。每个软件有独立介绍页，介绍内容使用 Markdown 维护。访客可以按软件名称搜索，也可以按 Markdown 配置的标签筛选。

本文件是实施计划；当前阶段不创建网站、不推送仓库，也不执行部署。

## 第一版范围

- 首页展示统一软件列表：图标、名称、简短介绍、来源标识和自定义标签；点击卡片进入详情页。
- 详情页顶部依次展示软件图标、名称、来源与定位标签、醒目的下载链接和次醒目的官网链接；分割线下展示支持图文结合的 Markdown 介绍，并提供返回列表入口。链接未配置时不显示对应按钮。
- 按名称即时搜索，忽略英文大小写，支持中文及部分名称匹配；标签可多选，多个标签之间采用「全部匹配」，搜索与标签筛选同时生效。提供清除条件和无结果提示。
- 响应式适配手机竖屏和电脑横屏，支持触摸与键盘操作、清晰的焦点状态、图片替代文本和基本无障碍语义。
- 支持渐进式 Web 应用（PWA）：在支持的设备上可添加到主屏幕或安装，并为已访问内容提供有限离线访问。
- 软件内容随网站构建生成，无需数据库、登录或后台；内容变更通过修改仓库文件完成。

## 响应式布局与 PWA

- 采用移动端优先的响应式布局，根据可用宽度而非设备型号调整：手机竖屏使用单列卡片和便于触摸的搜索、筛选控件；电脑横屏使用多列卡片和更宽的内容区。中间尺寸平滑过渡，避免横向滚动，并兼顾横屏手机、缩放和系统安全区域。
- 使用现代 HTML、CSS 和渐进增强：以语义化 HTML 和可读内容为基础，使用 Grid/Flex、弹性尺寸及媒体查询实现布局。服务端预生成的页面在脚本不可用时仍可阅读和打开详情；搜索和筛选需要浏览器脚本。
- 提供 Web App Manifest、适配图标、站点名称、主题色和独立窗口显示配置；通过 HTTPS 提供服务。安装入口遵循浏览器能力，部分浏览器需由用户通过浏览器菜单添加，不保证所有平台出现安装提示。
- 使用 Service Worker 实现有限离线能力：只预缓存体积小且必要的站点基础资源及离线提示页；已成功访问的详情页及必要静态资源可按需缓存。未访问的详情在离线时显示友好提示，不在首次访问时下载全部详情、搜索索引或图片。
- 缓存设置数量或容量上限及过期清理；HTML 和内容索引联网时优先获取更新，失败时使用可用缓存，带版本的静态资源可优先使用缓存。部署新版本后提示用户刷新以应用更新，避免正在使用时强制刷新；缓存不是永久存储，可能由浏览器清理。
- PWA 为增强功能，Service Worker 不可用或注册失败时网站仍可在线访问；不要求推送通知、后台同步或应用商店发布。

## 内容组织与维护

建议使用 Astro 静态站点及其 Content Collections：`src/content/apps/` 专门存放软件介绍，每个软件有独立文件夹，文件夹内包含 `index.md` 和 `images/` 图片文件夹。通过 frontmatter 保存结构化信息，正文用于图文介绍。构建时验证必填字段、来源取值、链接及本地图片路径；错误时明确提示文件位置，避免错误内容上线。

```text
src/content/apps/
└── example-app/
    ├── index.md
    └── images/
        ├── icon.png
        └── screenshot.png
```

示例 `src/content/apps/example-app/index.md`：

```markdown
---
title: 示例软件
description: 一句话介绍这个软件的用途。
origin: self
tags: [效率, macOS]
icon: ./images/icon.png
download: https://example.com/download
website: https://example.com
repository: https://github.com/example/example-app
---

## 软件介绍

这里用 Markdown 编写介绍、使用场景和功能。

![软件界面截图](./images/screenshot.png)

可以在图片前后继续添加说明文字。
```

- `title`、`description`、`origin`、`tags` 必填；`origin` 仅接受 `self` 和 `recommended`，界面分别显示「自己制作」和「推荐」。来源标识与自定义标签分开存储，但都显示在软件旁。
- `icon`、`download`、`website`、`repository` 为可选项；下载和官网分别显示为主按钮和次按钮，未配置时隐藏对应链接。未设置图标时显示统一占位图。正文图片使用相对于 `index.md` 的路径，图片应填写有意义的替代文字。
- 软件文件夹使用稳定、唯一的英文短名，例如 `example-app/`，生成 `/apps/example-app/`；修改文件夹名会改变链接，必要时配置重定向。
- 标签由作者自由配置，建议统一命名和大小写；标签筛选项从已发布内容自动汇总。
- 新增：复制软件文件夹并填写内容、放入图片；修改：编辑对应 Markdown 和图片；删除：删除整个软件文件夹。提交并推送后自动重新构建。删除或改名会使旧链接失效。

## 页面与交互

1. 首页 `/`：顶部悬浮搜索框、自动生成的标签筛选区、软件列表、分页控件和空状态。去掉站点标题、简介及「关于」等顶部文字；默认统一展示所有软件，不按来源分区，按名称排序。搜索框滚动时保持在顶部，适配手机安全区域，避免遮挡内容。
2. 详情页 `/apps/<软件文件夹名>/`：顶部展示图标、名称、来源标识和定位标签，下载链接作为醒目的主按钮，官网链接作为次按钮；分割线下展示支持图文结合的 Markdown 正文。
3. 404 页面：提示页面不存在，并提供返回首页的链接。

使用明确的页码、上一页和下一页切换，一次只展示当前页，不使用无限滚动、瀑布流或「加载更多」。搜索词、标签和页码保存在 URL 中，方便分享及从详情页返回时恢复；修改搜索词或标签时回到第一页。

## 按需加载与弱网体验

- 首次访问只加载首页首屏所需的页面、样式、最小交互脚本和当前显示的软件摘要，不预取其他软件的详情正文或页面。详情页使用普通链接，点击时只请求该软件的页面及其必要资源；关闭会触发批量预取的默认行为。
- 软件列表按页加载：构建时生成轻量的分页摘要数据，首页首屏仅包含第一页；点击页码、上一页或下一页时只请求目标页，替换当前列表。卡片图片和详情页非首屏图片使用懒加载，并指定尺寸，减少请求和页面跳动。
- 搜索与筛选使用单独的轻量索引，仅包含名称、标签、来源、短描述及详情路径，不包含 Markdown 正文或图片。构建时从所有已发布 Markdown 的 `tags` 自动汇总并去重，生成轻量标签清单供首页展示，无需单独维护标签；用户首次输入搜索或选择标签时才请求搜索索引；查询在整个目录范围内执行，结果也按页展示。索引体积增长后再按需评估分片，避免为少量内容引入额外复杂度。
- 控制资源体积：图片按实际展示尺寸压缩，使用合适格式；减少字体、第三方脚本和不必要依赖。优先使用系统字体；具体体积预算在有真实内容后按网络测试结果确定。
- 搜索索引、下一页和图片加载失败时展示明确提示和重试入口，保留已显示内容及筛选条件；避免依赖持续连接。对已成功获取且适合缓存的静态资源使用合理缓存策略，内容更新后通过带版本的资源地址或缓存失效机制确保访客获得新版本。
- 验证时在浏览器网络面板模拟弱网及请求失败，确认首次访问不请求全部详情和图片，交互后才加载对应资源，失败后可以重试。

## 技术与项目结构

- Astro：构建静态页面并读取、校验 Markdown；仅为搜索和筛选加载必要的浏览器脚本。
- GitHub：保存源代码、内容和图片，通过提交历史管理修改。
- Cloudflare Pages：连接 GitHub 仓库，自动构建和发布静态文件；本方案选用其现成的 Git 集成。Cloudflare 目前建议新项目也考虑 Workers，实施前可再次核对平台选项。
- 初步目录：`src/content/apps/` 存放软件 Markdown，`src/pages/` 存放页面，`src/components/` 存放组件，每个软件文件夹内的 `images/` 存放该软件图片，`docs/` 存放说明。
- 构建时生成 sitemap、页面标题和描述；外部链接采用安全的链接属性。Node 版本、依赖及锁文件在实施时固定，并在 README 记录本地运行方式。

## 实施步骤

1. 初始化 Astro 和 Git 仓库，确定依赖、格式化与构建命令，建立内容 schema 和示例 Markdown。
2. 实现首页、详情页、404 页面和响应式样式，确保两种来源共用同一列表。
3. 实现分页、按需加载的搜索索引、名称搜索、多标签筛选、URL 状态和空状态；完善基础无障碍与 SEO。
4. 配置 PWA 清单、图标和有限离线缓存；编写内容维护文档，检查新增、编辑和删除软件的流程。
5. 本地构建并验证手机竖屏和电脑横屏布局、Markdown 渲染、链接、搜索、标签组合、无结果和内容校验；在支持的浏览器验证安装、离线和版本更新。
6. 创建或连接 GitHub 仓库，推送代码；在 Cloudflare Pages 导入仓库，设置生产分支 `main`、构建命令 `npm run build`、输出目录 `dist`，验证生产和预览部署。
7. 在 Pages 项目的 Custom domains 中添加 `app.zhihaojiang.com`，按 Cloudflare 界面提示配置 DNS；验证域名解析、HTTPS、首页和详情页。配置前检查已有 DNS 记录，避免覆盖现有服务。

## 验收标准

- 一个软件只需新增包含 Markdown 和图片文件夹的软件目录，即可出现在首页并拥有详情页；修改或删除后重新构建正确生效。
- 自己制作和推荐的软件混合展示，来源标识正确；自定义标签与 Markdown 一致。详情页主次链接、分割线和正文图文展示正确，相对路径图片可正常加载。
- 中文、英文和部分名称搜索可用；多标签与搜索组合、清除条件、无结果和 URL 状态均正常。标签从 Markdown 自动汇总，无需维护单独的标签列表。
- 顶部搜索框滚动时保持可见且不遮挡内容；列表以明确页码分页，每次只显示当前页，切换筛选时回到第一页，返回时恢复状态。
- 移动端和桌面端可用，主要操作可通过键盘完成；构建遇到无效必填信息时失败并提示问题。
- 网络面板确认首屏不加载其他详情、全量图片或搜索索引；分页切换和搜索仅按需请求资源，弱网失败后可重试。
- 手机竖屏和电脑横屏均无横向溢出，触摸与键盘操作正常；支持安装的浏览器可安装 PWA，已访问内容可按缓存策略离线访问，未缓存内容显示离线提示，新版本可正常更新。
- GitHub 推送触发部署，预览和生产页面正常，自定义域名 HTTPS 可访问。
