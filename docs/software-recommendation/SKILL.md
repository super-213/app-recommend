# 软件推荐

为本项目的 Astro 软件目录制作可发布的推荐条目。先阅读项目根目录的 `README.md` 中「软件文档目录」和「Markdown 写法」，并检查 `src/content.config.ts` 和已有条目；以项目当前规范为准。

## 确认写作方式

识别软件及其官网。如果名称对应多个产品，先核实；用户提供的网址或明确描述优先。若用户尚未选择推荐内容的写法，询问并等待选择，同时可以先查证官网、检查现有条目并准备图片：

1. **参考官网**：依据官网的介绍、功能和措辞组织中文推荐内容，忠实表达原意，不大段照搬原文。
2. **帮我写**：根据经核实的资料独立撰写自然、易读的中文推荐，解释用途、适用场景和实际功能；官网有合适图片时，尽量图文结合。

用户已有明确选择时直接采用。两种方式都不得编造功能、价格、隐私承诺、系统要求或安装方式；不能确认的内容省略或明确说明。不要把商业软件误标为开源、免费或自主开发。尊重来源的使用条件，不绕过访问限制或复制大段受版权保护的文字。

## 收集资料和图片

- 优先查看软件官网、官方下载页和官方文档，核实名称、用途、平台、系统要求、安装方式和链接；需要时参考官方仓库或软件包管理器。区分下载地址和官网地址，不猜测 URL 或安装命令。用户未指定来源时，`origin` 使用 `recommended`；只有明确属于用户自己制作时才用 `self`。
- 从官网或其他可靠的官方来源寻找软件图标，下载到条目的 `images/` 中，优先使用清晰的官方图标；确认文件确实是可用图片而非 HTML 或错误页面，扩展名与格式一致。避免用网页 favicon 冒充软件图标。无法可靠取得时，省略 `icon`，告知用户，不要随意使用不相关图像。
- 用户选择「帮我写」时，官网有适合展示的产品截图或功能图片，且可获取、适合在项目中使用时，下载到同一 `images/` 目录，在相关段落附近通过相对路径引用并写清晰的替代文字。优先选择有助于理解功能的图片，避免装饰性堆砌；没有合适图片或无法取得时，以文字完成并说明。参考官网模式也可按用户要求配图。
- 核对图片内容、尺寸和格式，适当压缩，保留足以清晰展示的质量。记录素材来源以便最终告知用户；不伪造来源。不要绕过网站的访问或下载限制。

## 创建条目

1. 检查 `src/content/apps/` 中是否已有该软件。已有条目时在原目录完善，不创建重复条目；保留用户已有内容和其他无关改动。新条目使用唯一的小写英文、数字和连字符目录名，创建 `src/content/apps/<slug>/index.md` 与 `images/`。
2. 按项目 schema 写 YAML frontmatter：`title`、简短准确的 `description`、`origin`、`tags` 必填；取得图标时添加相对路径 `icon`。仅在已核实且适用时填写 `download`、`installCommand`、`website`、`repository`，可选字段无值时省略。沿用项目中已有标签命名，正确处理 YAML 特殊字符。
3. 用中文 Markdown 写清软件用途和主要功能；资料支持时补充系统要求、安装或使用注意事项。正文从二级标题开始，图片使用如 `![功能界面](./images/screenshot.png)` 的相对路径。文字应具体准确，不使用未经核实的宣传性结论。
4. 运行 `npm run build`，检查构建成功、条目路由及图片引用；修复由本次修改引起的问题。若无法完成某项检查，说明原因。最终告知用户创建或修改的文件、使用的素材来源、验证结果，以及未能取得的图标或截图。
